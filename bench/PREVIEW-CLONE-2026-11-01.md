# Preview clone experiment — 1 November 2026

A prototype reused the preview Sharp instance for LQIP after running `stats()` on a clone, avoiding the final `clone()`. The shipped 3.1.9 pipeline is the control. Seven fresh-process pairs ran serially on the existing 24-photo corpus, with three widths per photo, WebP quality 75, one warm-up batch and one timed 72-image batch. The first three pairs ran control first; the remaining four ran prototype first. OS caches were not flushed. Per-process peak RSS is reported, not heap size. The individual measurements and rejected patch are in `bench/results/preview-clone-2026-11-01/`.

Median time was 26.547 ms/image for control and 26.408 ms/image for prototype; median peak RSS was 206.28 and 206.56 MiB respectively. All runs produced the same digest of encoded bytes and preview metadata (`ee1c55ad14d99a99fe567d02899e1f44c5f70c981d315bc6d5bfee98657bee39`). This small local time difference does not establish a real performance benefit; the prototype also changes the processing fingerprint and therefore invalidates existing caches. It was rejected, and no production code changed. No Rust, cold-build, image-quality or general throughput improvement is claimed.
