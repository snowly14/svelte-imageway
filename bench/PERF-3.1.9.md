## Upgrade cache compatibility

Seven independent upgrade trials use a fresh Vite root per round and four fresh Node processes in sequence: published 3.1.8 cold, 3.1.8 warm, candidate first build without clearing caches, candidate warm. Each imports all 24 photos using the same default policies. The no-alias period (`upgrade.json`) measures **5609.40 / 85.79 / 5643.30 / 86.41 ms**; the selected reviewed compatibility mapping (`upgrade-selected.json`) measures **5508.59 / 82.31 / 81.87 / 82.03 ms**. These are separate local periods, not a network-cold or universal speed comparison. Without the alias, the first upgrade rebuild creates **198→396 transform** and **24→48 preview** cache files; 24 original PNG paths change while all 156 image-byte/SHA multisets remain identical. With the alias, all seven trials retain **198 transform / 24 preview** files, with identical names, sizes and modification times. All **156 image paths and bytes** remain unchanged. A separate hot same-root pair checks every one of **158 output files**, including generated JS and HTML, by path/size/SHA; all **222 cache files** also remain unchanged (`upgrade-parity.json`).

Only the precise full-tree implementation SHA `e3c96d43f9d137a68e28d89852216013ea7cb0f1868dc184df2a4331b380b03a` maps to the verified 3.1.8 revision. Every other implementation fingerprint invalidates normally. The source-diff proof, pinned Sharp clone analysis, limits/metadata/animation tests and security boundaries are in [ADR 32](../docs/adr/0032-reviewed-cache-equivalence.md) and `cache-equivalence-proof.json`. A dist-only prototype and its seven samples (`upgrade-alias.json`) remain as a separate experiment. Valid pre-existing caches, matching source, codec versions and policies are required; a cleared cache, changed policy or future processing change still rebuilds.

## Reproduce

Use Bun and serialize heavy suites. Verify/extract the pinned npm archive to `.local/component-3.1.9/baseline/package`; build and freeze a candidate package as documented in `artifacts.json`. Run `bun bench/perf-3.1.9/build-workers.ts baseline` before architecture edits, then `comparison --candidate=<frozen-package>` for cross-tool builds. Run `pipeline.ts`, `automatic.ts --pairs=7 --study=<new-label>`, `attributes.ts` (and `--local-provider` into a fresh output directory), `headless-bundle.ts`, `ssr.ts`, `client.ts --output-dir=<fresh-directory>`, and `verify-client.ts` serially. Preserve every old JSON before re-running; drivers that accept an output path/label must use a fresh location. Run `upgrade.ts` into separate study labels for the unaliased/selected candidates; use `--expect-reuse` for the selected candidate to assert unchanged cache metadata and asset paths. `upgrade-parity.ts` checks the complete hot output after `upgrade-selected`. The automatic driver also accepts `--candidate=<frozen-package>`; `automatic-three-way.ts --pairs=7 --study=<new-label>` requires the separately patched selective prototype and verifies its fingerprint. The pipeline script uses the candidate path recorded in its source. Create each frozen package explicitly.

The Rust preview module is unchanged at 14838 bytes and fixed 64 KiB. Its source fingerprint and independent rebuild remain required; no new browser WASM, consumer compiler, Rust/FFI speed claim, paid-cloud, image-quality, HTTP or market-leadership claim is made.
