# ADR 36: Preserve reviewed Node outputs while invalidating Edge cache policy

Status: selected locally, unpublished. Date: 1 November 2026.

The November changes preserve valid encoded Node outputs: signature checks avoid allocations; SVG uses the same pinned parser lazily; cache lifetimes reject NaN; PNG CRC is mathematically equivalent with exhaustive dimension/reference gates. The changed raster container inspector is called by Edge. No Node codec, quality, geometry, input bound, cache-policy identity, source-content key, worker admission or deadline changed. A complete compiled processing diff against the actual npm 3.1.9 archive is recorded in `bench/results/cache-split-2026-11-01/source-proof.json`. The selected Node/core code is byte-identical to the fresh-encoding control whose 156-image output multiset matches the baseline.

Add only the exact reviewed TS/WASM tree SHA-256 `12aa23a1e998811a0e5e7d70960fa6375af644312e826115ab19b54970cbcc94` to the existing compatibility map, sharing Node cache revision `b20ae906366d6af637b09e1d0f745f64638c030dfb49e3f5efab67454b7ad77f`. Every other fingerprint remains its own revision. The existing 3.1.9 reviewed mapping remains. Existing source-byte, codec-version, immutable configuration/limits and expiry checks are still key inputs/lookup checks; this does not authorize stale, corrupt or differently configured entries.

Edge does not reuse legacy entries: ADR 35 introduces the explicit `edge-v2` namespace plus the complete owned-policy fingerprint. This changes the hashed Edge key even when the compatible Node revision equals the old one. Shared-cache regressions cover lower input/pixel/output limits, unchanged-policy hits, and a seeded legacy key after the compatibility mapping is active. Future unreviewed processing changes also change the global revision normally. No extra public revision constant or API is required.

Seven trials from the verified actual npm 3.1.9 archive without compatibility have a first upgraded build median of 5570.33 ms, baseline warm 90.04 ms, and double entries from 198/24 to 396/48 transform/preview files. A separate seven-trial compatible period gives baseline warm 91.47 ms and first upgraded build 84.15 ms (subsequent 85.66 ms), preserving all 222 cache files by path/size/nanosecond mtime and all 156 image paths/bytes. These are separate local periods and valid-cache upgrades, not cold builds, network-cold installs or general codec speedups. One extra hot pair also compares all 158 emitted files, including JS/HTML, byte-for-byte and preserves all cache metadata. All raw samples and regressions remain recorded.

The build fingerprint helper now walks nested TS/WASM sources in the three processing directories instead of only their immediate children. It preserves the established flat-tree hash and forward-slash path order across platforms, rejects source symlinks rather than silently omitting them, and tests nested TS/WASM mutations and unknown-tree invalidation. Contributor build commands are unchanged. This makes the exact-source guard apply to future nested processing files too.

`node bench/edge-cache-transition.mjs` additionally loads the actual verified 3.1.9 Worker module and the selected module against the same cache and budget actor. Both use the same compatible Node marker. The legacy entry misses in the selected Worker, the following selected request hits, and the cache holds two different keys. The source and encoder are synthetic bindings for this cache-wiring proof; this is neither a live cloud nor codec test. The old Worker source SHA is pinned to the actual registry archive. Raw proof: `actual-edge-transition.json`.
