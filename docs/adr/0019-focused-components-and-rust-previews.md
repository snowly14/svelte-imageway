# Focused components and measured Rust previews

The user explicitly requested removal of the static variants and investigation of Rust/C++/Goose. Remove StaticImage/StaticPicture and both subpaths/types in major version 3. Image and Picture retain automatic local imports, provider delivery, snippets, native events, SSR and matching preloads. Background/metadata/headless helpers remain available.

Image encoding already uses Sharp's native C++/libvips stack. Replacing a TypeScript component with another language would not by itself improve codec throughput. The selected new native work is the optional 4x3 BlurHash projection, a bounded CPU loop that can be measured separately from native image decoding and encoding.

The Rust no_std kernel compiles to baseline WebAssembly with no imports, allocator, garbage collector or memory growth. One 64 KiB instance holds RGBA, sRGB/cosine lookups and 36 f64 coefficients. The synchronous typed host validates dimensions/length before copying; the Rust entry also rejects dimensions outside 1–32 before access. Host serialization owns the instance, with no asynchronous re-entry during calculation. Fixed-buffer access is the documented unsafe boundary. Hash packing/quantization preserves the reference encoder's component order and arithmetic. The Wolt algorithm attribution and MIT notice ship with the kernel.

The 1719-byte artifact is lazy-loaded on server/build paths only. Consumers do not install a Rust compiler or platform-specific addon. The manifest fingerprints source and artifact; build verifies both, and an independent Linux CI job recompiles using Rust 1.99.0 and compares exact bytes. The package test checks that the artifact/notice ship, removed APIs do not, and browser entries remain server-code-free.

Evaluation of Goose: [official compiler](https://github.com/aardappel/goose), [benchmark summary](https://github.com/aardappel/goose/blob/master/bench/summary.md), [working specification](https://github.com/aardappel/goose/blob/master/docs/goose_spec.md), reviewed 22 October 2026. Goose has a whole-program compilation model and C interop/export facilities, with inline data-stack storage. Its reported speed ratios are aggregates over sixteen benchmark workloads, on one machine, selecting fastest implementations per comparison; memory can select a different implementation. These are not image encoder measurements. Our fixed-buffer kernel already avoids allocation and teardown; the published Goose ratios do not establish a benefit over this Rust implementation. A Goose runtime/compiler integration remains unmeasured and is not shipped. This decision is about the tested deployment path, not a claim that Rust is universally faster.

Benchmark the reference JS, an optimized JS control with identical cached lookups, and the Rust host/kernel path. Include copies and packing, alternate fresh-process runs, verify identical hashes and complete preview bytes, and report cold initialization separately. Also compare full Sharp-plus-BlurHash previews to the published 2.0 baseline. Do not infer default LQIP, JPEG/WebP, HTTP, build-wide or browser gains from a small optional kernel.
