## Value proposition

Imageway's proposed value is lifecycle consistency: one bounded, versioned image request model drives build optimization, dynamic remote optimization, Svelte 5 presentation, CLI audit/optimization/deployment, adapter selection, and CDN/storage integrations. Provider changes should preserve component source code for the capability intersection. Unsupported transformations must surface clearly instead of silently changing meaning.

This is a product hypothesis. It is not evidence of superiority, measured performance, a unique invention, or an absence of competing features. Unpic already solves much of the component/provider problem; enhanced-img and imagetools already solve the common local-image case well. Building a replacement is justified only if the shared lifecycle materially reduces configuration and migration work.

## Build or reuse

Use Sharp as the Node encoder, not a new image codec. Evaluate existing engines in benchmarks and optional adapters. Keep the URL contract, artifact metadata, security policy, and Svelte presentation independent of any one backend. Do not add ipx or imagetools as a mandatory dependency alongside a duplicate Sharp pipeline: the duplicated transform vocabulary and cache semantics would undermine the single contract.

## Comparison evidence still required

No competitor was installed, executed, profiled, audited for security, or benchmarked in Phase 0. M10 must compare current pinned releases on identical licensed fixtures, widths, formats, qualities, concurrency, machines and cache states. Publish raw measurements, failed formats, setup costs, and limits. Do not describe the new package as faster, smaller, or more secure until those measurements support it.
